# 设计样本点、地图标注、邮箱身份与站内信设计

状态：已批准

日期：2026-09-16

适用范围：当前粮食商情统一工作平台的后端、企业 Web 前端和总览地图前端

## 1. 目标

在不改变现有系统功能框架、数据库地址和数据库实例的前提下，完成以下能力：

1. 依据全部启用地区的真实村界，为每个乡镇精确求解设计样本村最小覆盖集。
2. 在总览监测地图增加账号私有的点和矩形标注页签。
3. 注册时邮箱必填，支持手机或邮箱二选一验证，并增加邮箱验证码登录。
4. 增加站内信和邮件发送能力，永久保存用户主动发送的内容及投递结果。

## 2. 术语与边界

- **数据库迁移**专指数据库从一个地址、实例或服务器迁移到另一个地址、实例或服务器。本功能不涉及数据库迁移。
- **数据库结构升级**指在当前数据库中新增表、字段、索引和约束。
- **业务数据重填**指在当前数据库中复用、更新、新增或标记过期的设计样本点记录。
- 数据库地址、实例、连接方式和数据归属保持不变。
- 不修改正式样本点、年度样本网络、正式填报记录和历史业务记录。
- 不增加附件、群发、全员广播或管理员读取他人消息的能力。

## 3. 设计样本点覆盖规则

### 3.1 覆盖定义

- 处理系统内全部已启用且具备有效村界的地区。
- 每个行政村必须满足以下条件之一：
  - 本村被选为设计样本村；
  - 本村与至少一个设计样本村相邻。
- 每个乡镇至少选择 3 个设计样本村。
- 两个村的有效边界只要发生拓扑接触就算相邻，包括共享边界线段和仅有单点相碰。
- 完全分离或仅存在包围关系不算相邻。

### 3.2 精确求解目标

每个乡镇独立构建村级邻接图并运行确定性精确求解，按以下词典序目标选择结果：

1. 覆盖该乡镇全部行政村；
2. 入选样本村不少于 3 个；
3. 样本村总数最少；
4. 在同样最小的解中，优先保留已有且合规的设计样本村；
5. 仍有多个等价解时，按行政区划编码排序选择。

求解不依赖在线服务。相同边界版本、现有点位和算法版本必须得到相同结果。

### 3.3 现有记录复用和生命周期

- 已位于最终入选村且该村只有一条有效记录的设计样本点保留原 ID 和地点。
- 同一村最多保留一条有效设计样本点。
- 同村重复记录以及其他未落在最终入选村的现有记录，按稳定顺序重新分配到缺口村，并保留原 ID、创建时间和历史关联。
- 现有记录不足时新增。
- 完成全部分配后仍然多余的记录标记为“过期”，不物理删除。
- 过期记录不参与有效列表、地图显示、覆盖计算和后续业务选择，但历史和审计仍可追溯。

### 3.4 地点和坐标生成

- 区域编码使用真实行政村编码。
- 名称使用“`村名 + 设计样本点`”。
- 详细地址使用真实行政路径加系统生成说明，例如“市 / 县 / 乡镇 / 村 / 村内设计样本点”。
- 不虚构街道、门牌号或经营主体。
- 经纬度使用 WGS84，并且必须落在该村真实有效边界内。
- 坐标采用可复现随机生成，记录生成种子、算法版本和边界版本。
- 同村多个候选坐标不得重叠，并与边界保持安全距离。
- 页面刷新、服务重启或重复运行不得让既有坐标随机漂移。

### 3.5 预演和写入

正式重填前生成只读预演报告，至少包括：

- 地区、乡镇和村数量；
- 邻接边数量；
- 最优样本村数量；
- 保留、重新分配、新增和过期数量；
- 边界无效、求解无解和求解超时清单；
- 每个乡镇的覆盖证明。

每个乡镇独立事务写入。边界无效、无解或求解超时时，该乡镇不得写入正式结果，其他乡镇不受影响。

## 4. 地图标注页签

### 4.1 可见性和权限

- 在总览监测地图增加“地图标注”页签，市、县、乡镇、村四级共用同一能力。
- 只有选择该页签时才加载和显示当前账号的点或矩形；其他页签完全不渲染用户标注。
- 每个账号只能查看、覆盖和删除自己的标注。
- 管理员也不能查看或管理其他账号的标注。管理员账号仅用于验收自身标注流程。

### 4.2 持久化模型

- 每个账号仅保存一条当前标注记录，并由账号唯一约束保证。
- 标注类型为点或矩形。
- 新标注原子覆盖当前记录，不创建“失效标注”记录。
- 用户可以主动删除当前记录；删除后刷新、退出和重新登录均不得重新出现。
- 创建、覆盖和删除写入不可用于重新渲染图形的独立审计事件。

### 4.3 交互

- 单击且指针移动未超过拖拽阈值时生成点。
- 按住鼠标左键拖拽超过阈值时显示临时矩形。
- 拖拽过程中不弹出经纬度窗口、不写入数据库。
- 鼠标左键松开后才完成矩形、覆盖原记录、持久化并浮现右侧窗口。
- 点窗口显示单点经纬度。
- 矩形窗口只显示经纬度范围：最小经度、最大经度、最小纬度和最大纬度。
- 页签内提供“浏览地图 / 开始标注”状态；完成一次标注后自动回到浏览状态。
- 实现后必须在真实地图上验证点击、拖拽、缩放、平移以及市县镇村钻取的事件冲突，并仅调整事件竞争，不改变现有地图业务功能。

## 5. 邮箱注册与登录

### 5.1 邮箱身份

- 注册表单中邮箱必填，先标准化并校验格式。
- 邮箱地址全局唯一，比较时忽略大小写。
- 注册验证方式为手机验证码或邮箱验证码二选一。
- 选择邮箱验证并通过后，邮箱立即标记为已验证，可用于邮箱登录。
- 选择手机验证时，注册可以完成，但邮箱保持未验证；用户必须在账户中心补做邮箱验证后才能启用邮箱登录。

### 5.2 邮箱验证码

- 登录页增加“邮箱验证码登录”，布局和样式沿用现有手机验证码登录。
- 验证码有效期为 5 分钟。
- 验证成功一次后立即消费，不能再次使用。
- 新验证码发出后，同邮箱、同用途的旧验证码立即失效。
- 设置错误尝试上限和发送频率限制。
- 数据库只保存验证码安全摘要、用途、有效期、消费时间、尝试次数和发送状态，不保存明文验证码。
- SMTP 发送失败时不得产生可用验证码，界面不得显示虚假的“发送成功”。

### 5.3 SMTP

- SMTP 服务器使用 `smtp.qq.com:465`，采用 SSL/TLS。
- 发件地址使用 `7911945@qq.com`。
- SMTP 凭据必须使用 QQ 邮箱生成的客户端授权码，并通过生产密钥注入；不得使用或保存 QQ 网页登录密码。
- 源码、数据库、日志、设计文档和交付材料均不得记录明文 SMTP 授权码。
- 验证码邮件主题为“粮食商情统一工作平台验证码”。
- 验证码邮件正文为：

  ```text
  尊敬的用户，您好！
  欢迎使用粮食商情统一工作平台
  您本次的登录验证码为：XXXXXX
  ```

## 6. 站内信与用户邮件

### 6.1 入口与收件人

- 功能界面右上角增加信封入口。
- 有未读站内信时信封高亮并显示未读数量。
- 功能板块包含“收件箱”和“已发送”。
- 所有启用账号均可发送。
- 收件人仅支持完整用户名、完整手机号或完整邮箱精确匹配。
- 不提供模糊搜索、候选用户列表或账号目录枚举。
- 邮箱渠道只允许使用收件账号已验证的邮箱；没有已验证邮箱时拒绝邮件发送，但仍可选择发送站内信。

### 6.2 渠道与持久化

- 发送渠道单选为“站内信”或“邮箱”，不提供同时发送。
- 站内信持久化后立即进入收件人的收件箱并计入未读。
- 打开站内信时原子记录已读时间。
- 邮件先持久化正文和投递任务，再由事务外发送器通过 SMTP 投递。
- 邮件记录保存待发送、已发送或发送失败状态、尝试次数、错误摘要和时间。
- 使用幂等键防止重复点击产生重复消息。
- 用户主动发送的标题、正文、发送人、收件人、渠道和投递结果永久保存，不提供物理删除。
- 用户只能读取自己收到或自己发送的消息；管理员不能读取其他账号的消息。
- 验证码邮件使用独立验证码记录，不进入用户消息收件箱，也不永久保存明文验证码。

## 7. 当前数据库结构升级

本功能只在当前数据库实例内执行向前兼容的结构升级，不改变数据库地址或实例：

- 为设计样本点增加生命周期状态、过期时间和必要约束。
- 新增账号唯一的地图标注表和空间索引。
- 新增邮箱身份和邮箱验证码表。
- 新增永久消息、收件状态和邮件投递任务表。
- 所有新表和字段配置最小运行时权限、外键、唯一约束和数据完整性约束。

结构升级不得删除现有表、改变现有业务记录含义或覆盖正式填报数据。

## 8. 错误处理与安全边界

- 无效或缺失村界阻止对应乡镇生效，不使用最近村或虚假边界代替。
- 精确求解无解或超时时保留该乡镇现状，并输出明确异常。
- 地图标注的读取、覆盖和删除均以当前登录账号为服务端条件，不接受客户端指定其他账号。
- 收件人精确匹配接口只返回成功或统一失败，不泄露用户目录。
- 验证码、SMTP 授权码和登录凭据不得进入业务日志。
- 邮件正文和站内信正文按用户私有数据处理，仅发送人和收件人可读取。
- 发送频率、验证码频率和错误验证次数均受限，并记录安全审计。

## 9. 验收标准

### 9.1 设计样本点

- 全部已启用且边界有效的乡镇均有精确求解结果。
- 每个村被本村或相邻样本村覆盖。
- 每个乡镇至少 3 个有效设计样本村。
- 每个村最多一条有效设计样本点。
- 结果是最小覆盖解，并有可复核的覆盖证明。
- 合规记录 ID 得到保留；不足记录新增；多余记录过期。
- 所有新坐标位于对应村界内，重复运行结果一致。

### 9.2 地图标注

- 市、县、乡镇、村四级均能单击打点和拖拽矩形。
- 鼠标松开前不显示最终窗口、不持久化矩形。
- 点显示经纬度，矩形显示经纬度范围。
- 同一账号始终只有一个当前点或矩形。
- 标注只在地图标注页签显示。
- 管理员账号完成创建、覆盖、删除、刷新、退出、重新登录后确认已删除标注无残留。
- 点击和拖拽不破坏现有平移、缩放和钻取逻辑。

### 9.3 邮箱身份

- 注册邮箱必填且格式错误被拦截。
- 手机或邮箱二选一验证规则正确。
- 手机注册产生未验证邮箱，补验后才能邮箱登录。
- 邮箱验证码 5 分钟过期、成功后只能使用一次，新验证码使旧验证码失效。
- 真实 QQ SMTP 授权码可以成功投递注册和登录验证码。

### 9.4 站内信和邮件

- 精确用户名、手机号和已验证邮箱均能匹配收件人。
- 模糊搜索和目录枚举不可用。
- 站内信未读数量、图标高亮、打开已读和已发送列表正确。
- 邮箱渠道不产生站内信未读数。
- 用户主动发送内容和投递结果在数据库永久留存。
- 普通用户和管理员均不能读取其他账号的私有消息或地图标注。

## 10. 发布边界

- 源码测试、数据库结构升级、业务数据重填、服务健康、SMTP 实际投递、真实登录和公网浏览器验收分别记录证据，不互相替代。
- 发布说明必须明确：数据库地址未改变、数据库实例未改变、不涉及数据库迁移。
- SMTP 授权码未配置或真实发送未通过时，不得声称邮箱注册和邮箱登录已完成上线验收。
