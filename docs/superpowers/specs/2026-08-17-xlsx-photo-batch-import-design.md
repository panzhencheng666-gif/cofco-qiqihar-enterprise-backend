# XLSX 模板照片化批量导入与审核后自动发布设计

## 1. 目标与范围

本设计覆盖产情、市场、物流全部 XLSX 模板及其批量导入链路，目标是让业务人员能够下载统一契约的模板，填写允许缺省的业务数据，连同每个样本点的现场照片一次导入；导入结果先成为可继续补充的业务草稿，提交后由独立区域审核员审核，审核通过即由系统自动发布到业务查询、分析和报表链路，并通过现有实时事件机制同步刷新。

本阶段只实施和部署到本地环境，不授权云端、预生产或生产变更，不购买外部服务，不调整现有人员角色分配。

### 完成条件

1. 产情、市场、物流全部受支持模板使用同一套模板版本、字段、空值、照片和导入结果契约。
2. 每个非空样本点行必须引用 1–5 张有效现场照片；业务测量字段允许留空并可导入草稿。
3. 一次操作可选择一个 XLSX 和其中引用的多张照片，系统完成校验、上传、水印、绑定和逐行导入。
4. 导入草稿可补充、保存和提交；无合格审核员时只能保存草稿，不能进入无人可审的状态。
5. 填报人与审核人职责分离；审核通过后系统自动发布，不设置发布员或二次人工发布步骤。
6. 已发布数据进入现有数据库、查询、分析、工作台和实时联动链路；未审核草稿不得进入正式统计口径。
7. 本地迁移、自动化测试、实际 XLSX/照片导入、审批及双会话实时刷新验证全部通过。

## 2. 已确认的业务决策

### 2.1 宽导入、严提交

- 完全空白的行忽略，不记为失败。
- 非空行导入草稿所需的最小锚点是：样本点名称、地区、1–5 张现场照片。
- 品种、业务对象类型从用户所在模板和页面上下文确定，填报人及导入时间由登录会话生成。
- 调查期间可由导入页面当前期间补全；经纬度优先读取照片 EXIF，其次读取已登记样本点位置，两者均无时标记为“待补充定位”，仍允许保存草稿。
- 除上述锚点外，模板中的业务数据均允许留空；空值按真正的 `null` 保存，不转换为 0、空字符串或虚构默认值。
- 只有提交审核时才执行该业务对象的完整性、值域、照片、权限和审核路由校验。

“业务字段可留空”不等于“无身份的空行可入库”。样本点和地区用于识别草稿归属，照片用于满足每个样本点的现场证据要求；缺少任一锚点时该行返回明确错误，不生成不可管理的孤立记录。

### 2.2 照片操作方式

采用“一个 XLSX + 多个照片文件同批选择”的方式：

1. 每个业务模板最后增加列 `现场照片文件名（1–5张，分号分隔）`。
2. 用户在单元格中填写真实照片文件名，例如 `IMG_001.jpg；IMG_002.jpg`；中文或英文分号均接受，解析后统一规范化。
3. 导入时同时选择该 XLSX 和这些 JPG/JPEG/PNG 文件。
4. 系统按文件名匹配、校验、上传、生成水印副本并绑定到对应行。

不要求用户先上传照片再复制内部 UUID，也不把图片嵌入 XLSX。前者容易填错且不适合批量工作，后者在 Excel/WPS/LibreOffice 间兼容性差、文件体积大且提取行为不稳定。

### 2.3 审批与发布

状态链为：

```text
导入草稿 DRAFT
  -> 提交待审 PENDING_REVIEW
  -> 审核通过 APPROVED（同一事务内产生自动发布事件）
  -> 正式可见 PUBLISHED

PENDING_REVIEW -> 退回 RETURNED -> 补充后重新提交
```

- 填报人拥有创建、导入、读取、修改和提交权限。
- 区域 `BUSINESS_REVIEWER` 审核本权限范围内的数据。
- 提交人不得审核或退回本人提交的数据，即使同一账号同时拥有填报和审核角色。
- 审核通过后由系统自动发布，不设置发布员、不设置“待发布”人工队列，也不依赖人工点击第二次发布。
- 自动发布仅针对已审核业务数据进入正式查询、统计、分析和报表数据源；文档编排、外部报送等其他流程不在本阶段新增。
- 自动发布失败不得造成“已审核但数据未落地”的中间态：审批状态、正式记录和 outbox 事件在同一数据库事务中提交，事件投递可重试且幂等。
- 发现错误时走有审计记录的退回、更正或撤销流程，禁止直接覆盖历史已发布记录。

## 3. 统一模板契约

### 3.1 工作簿结构

每个模板至少包含：

- `填报说明`：模板版本、适用模块、字段说明、可选/必需规则、照片命名和导入步骤。
- `数据填报`：固定标题行、可筛选列、字段提示、数据校验和照片文件名列。

模板元数据必须是产情、市场、物流各对象字段的唯一来源。下载生成、XLSX 校验、导入映射、接口错误和自动化矩阵测试不得各自维护互相漂移的列清单。

### 3.2 单元格类型和空值

- 年份：整数，允许空，填写时范围为 1900–2200；模板校验从首条数据行开始，不得错误引用下一行。
- 月份：整数，允许空，填写时范围为 1–12。
- 数值：允许空；填写时按字段定义校验精度、上下限和单位。
- 文本：去除首尾空白后保存；纯空白视为 `null`。
- 枚举：提供下拉选项，同时由后端再次验证，不依赖客户端校验作为安全边界。
- 日期和期间：使用明确格式，解析失败返回单元格坐标与期望格式。
- 照片：每个非空行 1–5 个文件名，去重后计数。

模板必须在 Microsoft Excel、WPS 和 LibreOffice 至少能够打开、填写和保存，不显示错误引用或无效公式。旧模板版本在服务端收到后返回“模板版本过旧，请重新下载”，避免按错误列序静默导入。

### 3.3 文件名规范

- 批次内照片文件名必须唯一，按 Unicode NFC 规范化后精确匹配。
- 接受 `.jpg`、`.jpeg`、`.png`，但以真实 MIME 和完整图片解码结果为准，不能只信扩展名。
- 单张照片上限 10 MiB；图片像素和解压后内存设置安全上限，防止压缩炸弹。
- 拒绝路径分隔符、控制字符、隐藏路径和重复规范化名称，避免目录穿越或误绑定。
- 同一张照片可否被多个样本点引用默认为禁止；业务确需复用时应复制为不同文件并留下独立证据，避免样本证据混淆。

## 4. 数据模型与事务边界

### 4.1 统一导入草稿层

所有成功解析的行先进入受治理的导入草稿层，而不是把不完整值直接塞进现有产情、市场或物流正式表。建议新增扩展型迁移 V121，建立下列能力：

- `business_import_job`：批次、模板版本、领域、创建人、地区范围、总行数、成功/失败数和状态。
- `business_import_draft`：领域、品种、对象类型、样本点、地区、调查期间、业务值 JSONB、缺失项、完整度、创建人、版本号、源批次和源行号。
- `business_import_draft_evidence`：草稿与现场照片的有序绑定。
- 现有 evidence photo 领域约束扩展为支持导入草稿及物流正式记录。
- 幂等键和唯一约束用于阻止相同批次/行重放产生重复草稿或重复照片绑定。

这样可以保持现有正式领域表的不变量：正式表只承载达到提交要求并被提升的领域记录，统计和报表无需把“缺失”误当成 0。

### 4.2 草稿提升

用户在相应产情、市场或物流模块中打开导入草稿，补充后提交。服务端在一个事务中：

1. 锁定草稿版本并执行完整提交校验。
2. 确认存在覆盖该地区且与提交人独立的审核员。
3. 创建或更新对应正式领域记录为 `PENDING_REVIEW`。
4. 将照片从导入草稿受控绑定到正式记录，保留源批次和源行追溯。
5. 创建审核工作项和事务性 outbox 事件。
6. 标记导入草稿已提升，防止重复提交。

单行草稿、照片绑定、正式记录和事件必须原子提交。批次采用逐行事务：某行失败不回滚其他有效行，但同一行绝不允许出现“草稿成功、照片失败”或相反的半成品。

### 4.3 审核后自动发布

审核通过事务同时完成：

1. 校验审核人权限、地区范围、职责分离和记录版本。
2. 将正式记录置为 `APPROVED/PUBLISHED` 的业务可见状态。
3. 写入审核意见、审核人、时间及不可变审计轨迹。
4. 写入自动发布 outbox 事件。

下游事件消费者刷新查询索引、统计聚合、工作台和报表缓存。消费者失败可重试，不反向撤销已经提交的审核事务；用户界面显示同步状态，持续失败进入可观测告警和人工运维重放，而不是增加发布员。

## 5. 导入接口与用户体验

### 5.1 请求

批量导入接口使用受认证的 multipart 请求：一个 `.xlsx` 和若干照片文件，并携带模块、品种/对象、当前调查期间与客户端批次幂等键。接口仍执行现有地区权限校验，不能通过 XLSX 导入越权地区数据。

上传后先进入临时隔离区。服务端完成压缩包安全检查、工作簿版本校验、图片嗅探/解码、文件名映射后再逐行创建草稿。照片使用私有存储路径，记录 SHA-256、原始元数据和水印衍生物，不暴露本地绝对路径或公开直链。

### 5.2 返回结果

导入结果必须按行返回：

- 成功：草稿编号、源行号、照片数、完整度、待补充项和可打开链接。
- 失败：源行号、列名/单元格、稳定错误码、中文原因和修复建议。
- 批次汇总：总行数、忽略空行数、成功数、失败数、未被引用照片数。

存在失败行时，不把整个批次伪装成成功；有效行仍可使用。未引用或失败行占用的临时照片按保留策略安全清理，不能永久成为孤儿文件。

### 5.3 页面操作

产情、市场和物流页面统一提供：

- 下载当前版本 XLSX 模板。
- “导入 XLSX 与照片”多文件选择器，要求恰好一个 XLSX。
- 导入前摘要：识别的模板、数据行、照片数和明显缺失。
- 导入结果页：逐行错误、成功草稿、完整度和下一步入口。
- 草稿列表：按模块显示导入草稿，支持补充、保存、删除未提交草稿和提交审核。

## 6. 实时同步联动

沿用现有事务性事件与 SSE 链路，增加或统一以下事件：

- `IMPORT_JOB_PROGRESS_CHANGED`
- `IMPORT_DRAFT_CREATED`
- `IMPORT_DRAFT_UPDATED`
- `BUSINESS_RECORD_SUBMITTED`
- `BUSINESS_RECORD_RETURNED`
- `BUSINESS_RECORD_AUTO_PUBLISHED`

事件在数据库事务提交后可见。前端收到事件后按领域和地区失效对应缓存，刷新导入结果、草稿列表、待办、正式列表、概览统计和报表数据。未审核草稿事件只刷新填报侧，不进入正式分析口径；只有自动发布事件触发正式统计联动。

实时联动的验收以两个独立登录会话为准：填报人提交后审核人无需整页刷新即可看到待办；审核通过后填报人、查询页和概览在目标时限内自动更新。

## 7. 审核路由和异常状态

- 提交时查找覆盖该记录地区且有 `BUSINESS_REVIEWER` 权限的独立审核员。
- 没有合格审核员时，保留草稿并阻止提交，提示“当前地区尚未配置独立审核员，请联系系统管理员”；不得自动指定填报人本人，也不得绕过审核自动发布。
- 多名合格审核员时进入共享区域待办，首位通过乐观锁成功处理者完成审核。
- 审核期间记录被并发修改时拒绝旧版本操作，要求重新加载。
- 本阶段不修改生产人员角色，不新增发布员角色，也不将系统管理员自动视为业务审核员。

## 8. 安全、审计和可恢复性

- 所有上传执行文件大小、MIME、图片解码、像素、公式/外链、路径和 ZIP 膨胀率限制。
- 工作簿公式不在服务器执行；只读取允许的单元格值，拒绝宏文件和不支持格式。
- 照片水印至少包含采集/导入时间、地区、样本点和业务编号；原图及水印图均为私有证据。
- 导入、修改、提交、退回、审核和自动发布记录操作者、时间、前后版本和请求关联号。
- 数据库迁移只允许 expand-first；升级前保留本地运行时检查点，验证 V120 到 V121 和全新库两条路径。
- 重启只影响本地后端并使用既有受控运行脚本；健康检查失败时回到检查点，不触碰云端。

## 9. 验证矩阵

### 9.1 模板与解析

- 对全部 27 个已支持模板执行下载、列契约、首行公式、可空值、说明页和照片列测试。
- Excel/WPS/LibreOffice 打开、填写、保存后再次解析。
- 每种业务对象至少覆盖完整行、稀疏行、空行、非法数值、旧版本模板和列被移动场景。

### 9.2 照片

- 1 张和 5 张成功；0 张、6 张失败。
- 中文/英文分号、中文文件名、Unicode 规范化、重复名、未引用文件、缺失文件、同图多行引用。
- 扩展名伪装、损坏图片、超大文件、超大像素、目录穿越和重复上传。
- EXIF 定位、样本点定位回退和无定位草稿标记。

### 9.3 数据与审批

- 实际受保护测试数据库中的 multipart 导入、草稿保存、补充、提升和照片重绑定。
- 逐行部分成功、事务原子性、幂等重放和孤儿清理。
- 填报人不得自审；越区审核失败；无审核员时提交受阻；退回后可重提。
- 审核通过自动发布，无发布员、无待发布队列；正式查询和统计只读取自动发布后的记录。

### 9.4 实时和运行时

- 两个浏览器会话完成“导入 → 补充 → 提交 → 审核 → 自动发布”，验证待办和正式视图自动刷新。
- outbox 投递失败、重试和幂等消费测试。
- 源码构建产物与本地运行时绑定校验，后端重启后健康端点、Flyway 版本和关键接口检查。

## 10. 本地部署顺序

1. 固化统一模板元数据和模板版本，修复全部模板校验并增加照片列与说明页。
2. 以 V121 扩展导入草稿、照片领域和幂等/事件存储，不破坏 V120 现有表。
3. 实现 multipart 导入、图片安全处理、逐行草稿事务和结果接口。
4. 实现产情、市场、物流草稿提升，复用现有提交/审核权限并接通审核后自动发布。
5. 实现前端多文件导入、结果页、草稿入口和实时缓存刷新。
6. 运行完整验证矩阵，生成本地可恢复检查点。
7. 构建并更新本地后端和前端运行时，受控重启，执行两会话端到端验收。

每一步通过后留下边界明确的提交；不得重复已经通过且未受新改动影响的门禁。部署失败时只恢复本阶段本地产物，不覆盖用户已有工作树改动。

## 11. 使用流程

1. 进入对应产情、市场或物流填报页面，选择品种/对象和调查期间。
2. 下载最新 XLSX 模板，先阅读 `填报说明`。
3. 每个样本点填写样本点名称、地区和 1–5 个照片文件名；其他业务字段可先留空。
4. 把照片保留为独立 JPG/JPEG/PNG 文件，确保名称与单元格完全一致。
5. 点击“导入 XLSX 与照片”，一次选择一个 XLSX 和全部被引用照片。
6. 查看逐行结果；打开成功草稿补充数据，保存后提交审核。
7. 独立区域审核员在“待我处理”中审核；通过后系统自动发布并实时更新业务列表、概览、分析和报表，无需发布员再次操作。

## 12. 非目标

- 不部署或切换云端、预生产、生产流量。
- 不购买对象存储、消息服务或其他付费资源。
- 不在本阶段批量调整用户、地区权限或审核员配置。
- 不支持将图片嵌入工作簿，也不要求用户接触内部照片 UUID。
- 不将未审核草稿纳入统计、分析或正式报告。
- 不把“本地验证通过”表述为生产已经上线。
