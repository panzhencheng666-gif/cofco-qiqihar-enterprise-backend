# 供需平衡增量计算与库存去重设计

## 1. 目标

供需平衡按当前已经人工审核并正式发布的数据持续计算，不等待本期所有任务全部通过。待审核、被驳回和已作废记录不进入正式计算；后续记录审核发布后，系统自动刷新同一产品、地区和期间的结果。

本设计同时解决以下问题：

- 已有核定数据时不得整项显示“暂无数据”；
- 产情、市场和物流按各自业务职责提供事实，不互相冒充；
- 产情农户库存和市场企业库存属于不同持有环节，默认分别汇总；
- 只在同一业务域内部排除确定重复，不能误删正常记录；
- 少数库存冲突只影响冲突组，不阻塞填报、人工审核、正式发布和其他指标计算；
- 不向在线表单、业务列表或 XLSX 增加库存权属等填报字段。

## 2. 非目标

- 不改变现有行政区划和地图边界；
- 不把市场采购量、销售量直接当作区域流入或流出；
- 不用零值替代缺失事实；
- 不因去重结果退回业务记录或产生新的草稿流程；
- 不在业务界面暴露数据库字段码、算法名称、版本号或开发过程信息；
- 不在本阶段设计报告中心和日报、周报、月报导出。

## 3. 业务事实分工

| 业务域 | 核定后提供的供需事实 | 不承担的职责 |
| --- | --- | --- |
| 产情 | 预计总产、生产端期初库存、生产端期末库存、自用数量 | 不提供企业市场库存，不提供区域物流流量 |
| 市场 | 企业端当前/期末库存、市场价格、采购量、销售量 | 采购量和销售量不直接替代区域流入、流出 |
| 物流 | 区域流入量、区域流出量、物流运价 | 不作为库存来源 |

产情样本是生产端主体，市场样本是企业主体。两类库存默认属于不同持有环节，不因同时存在而互相排除。

## 4. 增量计算规则

### 4.1 正式记录范围

每次计算只采用满足以下条件的记录：

1. 已人工审核并正式发布；
2. 与查询的产品、地区、年度和月份一致；
3. 位于当前账号授权地区范围内；
4. 是同一业务身份在查询截止时间前的最新正式有效版本。

待审核记录不进入计算，但不会阻止同范围内已审核记录先行计算。被驳回和已作废记录不进入计算。

### 4.2 组件先算、完整等式后算

只要某个组件存在核定数据，就展示该组件的真实计算值和来源数量：

- 有预计总产就显示预计总产；
- 有生产端库存就显示生产端库存；
- 有企业端库存就显示企业端库存；
- 有物流流入或流出就分别显示对应流量；
- 有自用数量就显示自用数量。

某个组件缺失时，仅该组件显示“缺少核定数据”。不得因为一个组件缺失而把其他已有组件置空，也不得把缺失项当作零。

完整供需等式为：

`期初可观测库存 + 预计总产 + 区域流入 = 自用 + 区域流出 + 推算其他消耗 + 期末可观测库存`

只有等式所需组件全部具备且库存冲突已经处理时，才计算“推算其他消耗”并标记完整结果可用。此前页面展示“当前核定范围的部分结果”，而不是伪造完整结果。

### 4.3 库存分层汇总

在同一产品、地区和统计截止时点下：

`期末可观测库存 = 生产端有效期末库存 + 企业端有效期末库存`

`期初可观测库存 = 生产端有效期初库存 + 可取得的企业端期初库存`

企业端期初库存优先采用同一企业库存位置的上一统计期间正式期末快照自动结转。没有上一期正式快照时，企业端期初库存保持缺失，不以当前库存或零值替代。即使企业端期初缺失，已经存在的生产端期初库存仍应单独展示。

## 5. 库存域内去重

### 5.1 去重边界

产情只与产情记录比较，市场只与市场记录比较。产情农户库存与市场企业库存不做跨域去重。

物流记录不参与库存去重。

### 5.2 库存位置身份

系统从已有业务字段派生库存位置身份，不要求员工增加填报字段：

`业务域 + 统一样本点身份 + 产品 + 地区/经纬度位置 + 统计期间 + 期初或期末`

统一样本点身份继续依据规范化后的样本点名称、联系方式和地区建立，且与具体产品无关。产品只属于库存位置和业务记录，不属于样本点计数身份。

同一家企业可以有多个库存位置。同一企业两个不同实际位置的仓库分别填报 300 吨和 200 吨时，两条均进入计算，企业库存合计为 500 吨，企业仍只计为一个样本点。

### 5.3 自动处理范围

系统只对确定性情况自动处理：

- 同一业务记录的更正版本：采用最新审核版本，旧版本保留审计但不参与计算；
- 同一导入任务重复提交：依靠幂等键和正式业务身份只形成一个当前有效记录；
- 同一业务域、同一库存位置、同一产品、同一期间和同一库存类型的完全重复记录：库存只采用一次。

名称相似、联系方式相近、坐标接近但不完全一致的记录不得自动合并。此类记录仅形成库存复核提示，正常业务记录仍可审核发布。

### 5.4 冲突局部化

同一库存位置出现多个不同库存值且无法由正式版本关系解释时：

- 原始业务记录保持其审核和发布状态；
- 价格、产量、销量和其他无冲突事实继续参与各自指标计算；
- 只有该库存位置进入“库存口径待复核”；
- 其他无冲突库存位置继续计算；
- 页面显示已采用数量、待复核数量和当前可计算合计，不得把整个库存域置为“暂无数据”。

复核完成后，系统保存采用记录、被排除记录、处理人员、时间和原因，并自动重新计算受影响范围。

## 6. 技术数据与业务字段边界

在线表单、业务目录列表和 XLSX 不增加任何库存去重输入字段。

数据库可维护以下系统派生信息，但它们不是业务填报字段：

- 统一样本点标识；
- 库存位置标识；
- 当前有效版本；
- 重复组标识；
- 计算采用或待复核状态；
- 采用来源和审计轨迹。

这些信息必须由现有业务事实派生，不得成为业务记录审核通过的必填条件。

## 7. 页面呈现

供需平衡页面按当前筛选范围显示：

- 生产端已核定库存；
- 企业端已核定库存；
- 当前已核定可观测库存合计；
- 已采用记录数；
- 待审核记录数；
- 库存待复核组数；
- 数据截止时间。

状态文案只使用业务语言：

- “当前核定范围结果可用”；
- “部分数据待补齐”；
- “库存口径待复核”；
- “当前范围暂无核定数据”。

“暂无核定数据”仅能在该组件实际没有任何可采用正式值时出现。有可采用值但覆盖不完整时，必须显示数值并标注“当前核定范围”。

库存待复核入口只对有相应权限的人员显示。它是独立计算复核入口，不是业务填报字段，也不是草稿或审核退回流程。

## 8. 实时同步流程

1. 填报或 XLSX 导入完成自动校验；
2. 合格记录进入待人工审核；
3. 审核通过后，同一事务将记录转为正式有效状态并写入业务事件；
4. 业务事件通知总揽监测、产情分析、市场分析、物流分析和供需平衡；
5. 各消费者按统一产品、地区、期间和有效版本口径重新查询数据库；
6. 待审核记录后续通过时，仅重算其影响范围；
7. 驳回、作废或更正发布时，同样重算其影响范围。

前端缓存不得成为正式计算来源。事件连接暂时中断时，页面保留最近一次正式快照并在恢复后重新查询。

## 9. 异常和安全规则

- 负库存、非法单位和非法统计期间仍属于业务校验错误，应在提交审核前明确提示；
- 疑似重复不属于导入格式错误，不得阻止导入、审核或发布；
- 去重服务异常时保留已核定业务数据，不把未完成判定的数据默认为零或直接相加；
- 单个冲突不得影响无关产品、地区、期间和指标；
- 所有自动选择和人工复核必须可追溯到原始正式记录。

## 10. 验收标准

### 10.1 后端契约

- 已审核记录立即进入同范围计算，待审核记录同时存在时不阻塞；
- 待审核、驳回和作废记录不进入正式值；
- 产情库存与市场库存按不同环节汇总，不再触发全局互斥阻塞；
- 同域完全重复只计算一次；
- 同一企业不同仓库分别计算；
- 更正版本只采用最新正式版本；
- 一个冲突组只排除该组库存，其他库存继续计算；
- 有任一可采用值时返回该值、来源数和覆盖状态，不返回全域空值；
- 缺失值不以零替代。

### 10.2 前端契约

- 有核定数据时显示真实数值和“当前核定范围”；
- 缺失组件单独标记，不清空其他组件；
- 待审核数量和待复核数量可见但不计入正式值；
- 不显示技术字段码、开发过程文案或草稿流程；
- 审核发布事件到达后自动刷新，不要求人工重新计算。

### 10.3 端到端场景

至少覆盖以下受保护测试库场景：

1. 一条产情记录审核通过、其余仍待审核时，预计总产立即更新；
2. 一条市场企业库存审核通过时，企业端库存立即显示；
3. 一条物流流入审核通过时，仅流入组件更新；
4. 生产端库存和企业端库存同时存在时分别展示并合计；
5. 同域重复导入不重复累计；
6. 同一企业两个不同仓库都进入合计；
7. 一个库存冲突组待复核时，其他正常库存仍有结果；
8. 更正版本审核发布后替代旧版本并触发实时刷新；
9. 浏览器只通过本地唯一入口验收，控制台无错误，正式数据库记录数量不被测试修改。

## 11. 实施边界

实施必须先在 `qiqihar_enterprise_test` 重放迁移并完成回归，再部署本地运行副本进行浏览器验收。不得修改云端或生产环境，不得清理、覆盖或提交现有未提交改动，不得改变地图行政区边界。
