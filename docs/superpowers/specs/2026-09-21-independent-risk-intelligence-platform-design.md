# 独立风险研判预警与领域 AI 平台设计

## 目标

在现有齐齐哈尔粮食商情企业平台的“应用中心”增加与“业务工作台”平级的“风险研判预警”应用。该应用拥有独立前端、后端、数据库、模型服务、训练调度和运行审计；复用现有统一登录，并通过只读接口或增量事件获取真实业务数据。风险应用的故障、训练和升级不得影响现有应用中心、业务工作台或正式业务数据。

系统应形成可审计的自主适应能力：持续读取真实业务变化，形成独立研判和预警，根据后续真实结果积累案例与训练样本，每日自动评估和训练，达到质量门槛后自动晋级，退化时自动回滚。这里的“自主”指有边界的独立判断、长期记忆、自我评估和模型适应，不宣称模型具有人类意义上的意识或主观体验。

## 已确认的产品边界

- 应用入口固定为 `系统首页 → 应用中心 → 风险研判预警`，不把风险系统放进业务工作台。
- 风险系统内部的返回动作统一返回应用中心，不跳转到业务工作台。
- 现有系统只增加应用入口、统一登录授权和只读数据出口；不改变现有业务流程、权限语义或正式数据表。
- 风险系统的研判、预警、反馈、记忆、训练数据、模型版本和审计记录均进入独立数据库。
- 不展示静态指标、演示记录、虚假健康状态或没有真实持久化行为的按钮。
- 常规模型训练和晋级不需要人工审批；紧急停机、冻结和回滚属于运行保护，不是日常审批环节。
- 本地完整验收后再发布云端；云端具备独立训练能力，不依赖本机持续在线。

## 方案选择

### 采用方案：开放基础模型上的自主领域 AI

系统不从零预训练通用基础大模型，而是采用可私有部署、可替换的开放基础模型，并自主建设以下核心资产：

- 粮食风险领域数据规范与时间点样本集；
- 风险特征、确定性规则和概率分类模型；
- 检索增强、案例记忆和知识有效期治理；
- 结构化独立研判与反证机制；
- LoRA/QLoRA 领域适配器及其训练管线；
- 评估集、质量门槛、影子运行、自动晋级和回滚；
- 模型、数据、提示模板和输出的完整审计链。

当前 `mlx-community/Qwen3-0.6B-4bit` 只作为本地训练链路的启动模型，不被定义为最终生产模型。最终模型规格在本机和云端分别完成内存、显存、吞吐、质量和稳定性基准后确定。基础模型通过适配层接入，未来替换基础模型时保留领域数据、记忆、评估集、模型治理记录和业务 API。

### 未采用方案

- **从零预训练通用大模型：** 对语料、GPU 集群和训练周期要求过高，不能保证在当前项目约束下优于成熟开放模型。
- **完全依赖外部闭源模型 API：** 无法满足独立运行、数据边界、长期训练、可迁移和供应商解耦要求。
- **在现有业务后端和数据库中直接运行训练：** 会引入资源争用、表膨胀、迁移耦合和故障传播，违反“不影响现有系统”的硬边界。

## 一、总体架构

系统由以下独立组件组成：

1. **风险应用前端**：提供态势、事件、研判、预警、记忆、模型进化和运行审计界面。
2. **风险 API 服务**：承担身份映射、查询、案件状态机、权限、审计和对外 API。
3. **只读数据连接器**：从现有平台的版本化只读 API 或增量事件中获取业务事实，维护同步游标和来源水位。
4. **风险评估引擎**：执行确定性规则、变化检测、异常检测和概率分类，生成可重放的风险评估。
5. **AI 研判服务**：结合业务事实、风险特征、检索证据和领域模型生成结构化研判。
6. **长期记忆与检索服务**：管理案例记忆、知识记忆、有效期、来源和撤销状态，为研判提供可引用上下文。
7. **训练与评估服务**：构建时间点数据集，训练分类器和 LoRA 适配器，完成离线评估和影子比较。
8. **模型注册与激活服务**：保存不可变模型工件、内容哈希、评估结果、生命周期和激活/回滚记录。
9. **调度与恢复服务**：负责每日训练、错过任务补跑、租约、防重和失败重试。
10. **独立 PostgreSQL 与模型工件存储**：只保存风险系统数据；工件以不可变版本和 SHA-256 管理。

现有平台与风险系统之间只有三条受控通道：

- 统一登录签发给风险应用的独立 audience/token；
- 真实业务数据的只读接口或增量事件；
- 经明确授权的站内通知接口。通知接口不能修改业务事实或审批状态。

现有系统不可用时，连接器停止推进水位并保留最后成功快照；风险系统必须明确显示数据陈旧状态。风险系统不可用时，现有系统继续独立运行。

## 二、数据与责任边界

### 业务事实

业务事实仍以现有系统的正式提交记录和审计事件为准。风险系统保存带来源的不可修改快照，至少包含：

- 来源系统、来源记录 ID 和来源版本；
- 业务发生时间、提交时间和同步时间；
- 数据责任区域、业务域和可见范围；
- 内容哈希、同步批次和连接器游标；
- 是否已在来源系统被更正或撤销。

只读连接器使用最小权限账号，数据库级或 API 级策略均禁止对现有业务表写入。连接器必须限流、分页、支持断点续传，并保证相同来源版本重复投递不会生成重复事实。

### 风险系统数据域

独立数据库至少包含以下逻辑数据域：

- `integration`：来源快照、同步游标、失败批次和数据新鲜度；
- `risk`：评估、事件、状态时间线、处置建议和最终结果；
- `judgement`：结构化 AI 研判、引用证据、反证、不确定性和提示/模型版本；
- `memory`：案例、知识、假设、有效期、来源和撤销记录；
- `training`：样本快照、特征快照、数据集清单、训练执行和评估切片；
- `model`：模型版本、工件哈希、影子比较、激活事件和回滚事件；
- `notification`：通知意图、投递尝试、接收范围和最终状态；
- `audit`：访问、操作、自动决策和运行保护事件。

所有训练样本必须能反向定位到当时可见的业务事实和最终结果。模型输出本身不能直接成为真值标签。

## 三、真实研判与学习闭环

### 在线研判

每次业务增量触发以下可重放流程：

1. 连接器持久化带版本的业务事实快照；
2. 评估引擎计算确定性规则、变化特征和模型概率；
3. 检索服务只返回在研判时间点已经存在且对当前用户可见的证据；
4. AI 服务生成符合固定 JSON Schema 的研判；
5. 风险 API 在同一业务事务边界内保存评估、研判、证据引用和模型版本；
6. 达到预警策略时创建预警意图并异步投递；
7. 后续业务事实、处置过程和最终结果追加到事件时间线。

AI 研判必须包含：

- 风险结论与风险等级；
- 支持证据及其来源 ID；
- 反面证据；
- 不确定因素和缺失数据；
- 置信度及其校准版本；
- 可能演化路径；
- 推荐措施及其适用条件；
- 基础模型、适配器、分类器、知识快照和提示模板版本。

证据不足时必须输出“证据不足/暂缓判断”，不能通过语言流畅度掩盖数据缺口。解析失败、引用不存在或模型超时的输出不得写成有效研判。

### 独立意见与假设

模型可以根据跨案例模式提出“风险假设”或“规则候选”，但必须与已确认事实分区保存。每个假设包含支持证据、反证条件、适用范围、创建模型版本和后续验证状态。假设可以参与检索和离线评估，但在被真实结果验证前不能作为训练真值，也不能自动修改程序、权限、业务记录或正式规则。

### 每日训练

每日任务按以下顺序执行：

1. 取得分布式租约并检查是否存在未完成的同一数据水位任务；
2. 固化训练截止水位，构建点时正确的数据集；
3. 排除结果未知、证据不足、来源已撤销和可能发生结果泄漏的样本；
4. 按时间顺序划分训练、验证和保留集，不随机混入未来数据；
5. 训练风险分类器，并在满足最小新增样本量时训练领域 LoRA/QLoRA 适配器；
6. 在总体、风险等级、业务域、区域和时间切片上执行离线评估；
7. 注册带内容哈希的候选模型并进入影子运行；
8. 使用同一时点输入比较正式模型和候选模型；
9. 达到质量门槛和最小影子周期后自动激活，否则自动拒绝；
10. 持续监测正式模型，出现显著退化时自动回滚到上一稳定版本。

没有足够真实标签时任务记为 `SKIPPED_INSUFFICIENT_LABELS`，保存实际样本数和最低要求；不得生成合成业务事实、伪造训练成功或填充评估指标。

### 自动晋级门槛

门槛由版本化策略管理，至少覆盖：

- 最小真实标签数和最小新增标签数；
- 最小影子运行时长和最小影子样本数；
- 召回率、精确率、F1、误报率和概率校准；
- 相对当前正式模型的最大允许回归；
- 各关键业务域和区域切片不得出现严重退化；
- 输出结构合规率、证据引用有效率和拒答正确率；
- 推理延迟、错误率和资源使用上限。

自动激活和自动回滚均写入不可篡改审计记录。管理员拥有紧急冻结、停训和回滚能力，但不设置常规人工审批队列。

## 四、长期记忆

长期记忆分为三层：

1. **案例记忆**：风险事件在研判时看到的事实、实际演化、处置过程和最终结果。
2. **知识记忆**：有来源的业务规则、术语、政策、区域知识和时效范围。
3. **模型记忆**：训练数据清单、适配器、分类器、评估结果、失败原因和激活历史。

每条记忆保存来源、创建时间、适用范围、有效期、可信等级和撤销状态。知识过期后自动降低检索权重而不是物理删除；来源被更正时建立替代关系并触发受影响研判的重评估。检索结果按权限过滤，并把实际引用的记忆 ID 固化到研判记录中。

每日反思任务只做结构化归纳：识别重复失败、未覆盖模式、规则候选和数据缺口。反思内容进入假设区，不直接修改模型、规则或权限。只有真实标签和版本化知识才能进入正式训练集。

## 五、产品功能与交互

### 1. 风险态势总览

展示真实风险总数、等级分布、变化趋势、区域、业务环节和数据新鲜度。所有指标均可下钻到对应事件和来源记录。查询结果为空时显示“尚无符合条件的真实数据”，不以零值图形或样例数据制造繁荣感。

### 2. 风险事件中心

管理发现、研判、预警、跟踪、解除和最终结果。每条事件拥有稳定编号、状态机、来源、时间线、责任范围、证据链和最终结果。状态变更必须持久化并审计。

### 3. AI 独立研判中心

以事实、支持证据、反证、不确定性、演化路径和建议的结构展示模型意见。追问只允许基于当前用户可见的事实和记忆回答；回答必须返回引用，不能把新对话内容写成正式业务事实。

### 4. 智能预警中心

依据风险等级、变化速度、影响范围和版本化策略创建预警。展示真实接收范围、投递尝试、失败原因、重试状态和最终结果。没有收到下游确认时不能显示“发送成功”。

### 5. 知识与长期记忆中心

提供案例、知识、失败判断、成功模式、来源、有效期和撤销链的检索与查看。事实、模型假设和已验证模式使用不同视觉和状态标识。

### 6. 模型进化中心

展示真实训练样本量、数据截止水位、训练执行、评估指标、影子结果、正式版本、激活和回滚记录。样本不足、训练失败或指标缺失时显示具体原因，不使用固定“正常”状态。

### 7. 运行与审计中心

展示连接器水位、数据新鲜度、风险 API、推理、训练、调度、通知和存储状态，并提供真实错误、最近成功时间和关联执行 ID。健康状态必须由实时探针和数据库记录计算。

### 视觉方向

采用克制的未来科技风：深蓝灰导航框架、柔和浅色内容区、少量青绿色状态光和清晰的高密度信息层级。避免满屏霓虹、纯黑背景、无意义动画和大面积重复卡片。动效只用于风险变化、数据流和训练进度，并遵循 `prefers-reduced-motion`。颜色不是唯一状态表达方式，所有状态同时使用文字或图标。

任何按钮都必须连接真实 API 和持久化结果；尚未实现的能力不在正式界面出现。长操作显示真实阶段和执行 ID，页面刷新后可继续读取进度。

## 六、API 与状态约束

风险系统 API 使用独立 `/api/v1/risk-intelligence` 命名空间。核心资源包括：

- `/source-status`：只读连接器水位与新鲜度；
- `/assessments`：风险评估和特征快照；
- `/events`：风险事件、时间线和最终结果；
- `/judgements`：结构化 AI 研判与引用；
- `/warnings`：预警意图和投递状态；
- `/memories`：权限过滤后的长期记忆；
- `/training-runs`：训练和评估执行；
- `/model-versions`：候选、影子、正式、拒绝和回滚版本；
- `/operations/health`：组件健康与最近成功时间。

写操作使用幂等键和乐观版本。异步训练、重评估和通知返回持久化执行 ID；客户端通过状态资源或事件流读取进展，不依赖单次长连接保持成功。所有列表接口分页并有稳定排序。

## 七、故障、降级与安全

- 模型服务不可用时，不生成替代文本或伪造 AI 结论；确定性规则可以继续产出明确标记的规则评估。
- 训练失败不影响当前正式模型；候选工件只有在写入完成并通过哈希校验后才能注册。
- 数据源延迟时显示最后成功水位和陈旧时长，超过策略阈值时暂停依赖新数据的预警。
- 通知失败使用有上限的指数退避和死信状态，不重复创建风险事件。
- 进程重启后通过数据库租约和执行状态恢复，不重复激活模型或重复投递通知。
- 风险应用使用独立 SSO 客户端/audience、最小权限服务账号和独立密钥；密钥不写入代码库或浏览器包。
- 原始业务快照、研判、训练集和模型工件按职责授权；日志脱敏，不记录访问令牌和无关个人信息。
- 模型输出按不可信内容处理，执行结构校验、引用校验、长度限制和提示注入隔离。
- AI 没有修改程序、提升权限、调用未授权外部服务或写入现有业务系统的能力。

## 八、本地部署

本地以独立运行单元安装：

- 风险前端生产构建；
- 风险 API 服务；
- 独立 PostgreSQL；
- 使用 Apple Silicon/MLX 的推理训练服务；
- 调度与健康监督；
- 独立模型和备份目录。

macOS 使用受控后台服务定义实现登录/重启后自动启动、崩溃恢复和日志轮转。服务依赖通过健康检查排序，训练任务支持错过时间后的补跑。配置和密钥保存在权限受限的外部文件或系统密钥存储中，不进入 Git。

本地模型选择先进行硬件基准。`Qwen3-0.6B-4bit` 继续用于管线烟雾验证；生产候选必须在实际机器上满足内存、延迟、训练时间、结构化输出正确率和质量门槛后才能启用。

## 九、云端部署

云端在独立运行边界内提供：

- 风险前端和 API 容器；
- 与现有系统共用同一个 PostgreSQL RDS 实例，但使用独立的 `qiqihar_risk_intelligence` 数据库；
- 独立对象存储和版本保留策略；
- 在线推理节点；
- 可持续运行的 GPU 训练节点或满足基准的等效训练资源；
- 调度、队列、监控、日志、备份和告警。

共用 RDS 只共用实例资源，不共用数据库、schema、账号或连接池。风险数据库使用独立的数据库所有者、Flyway 账号和运行账号；这些账号不得拥有现有业务数据库中的表、序列、函数或 schema 权限。风险服务不启用 `dblink`、外部数据包装器或跨库查询，业务事实仍只能通过版本化只读 API 或增量事件进入风险数据库。

风险连接池设置独立的最大连接数、语句超时、锁等待超时和空闲事务超时。模型工件、LoRA 权重、原始训练文件和大体积日志不写入 RDS，而是进入独立对象存储。上线前对共享 RDS 执行容量和压力门禁；如果 CPU、内存、连接、IOPS、存储或业务延迟余量不满足门槛，则先扩容 RDS 或改用独立实例，不允许带风险上线。

在线推理与训练分离，训练节点资源耗尽或重启不影响正式推理。云端每日自行构建数据集并训练，不依赖本机同步模型。模型工件通过注册服务在训练和推理节点间发布，并在加载前校验哈希。

风险应用通过现有域名下的独立路径或独立子域接入，但网络、数据库连接池、计算配额和发布流水线与现有业务服务隔离。上线采用功能开关和灰度访问；关闭风险应用时，应用中心和业务工作台继续工作。

在读取云服务器 CPU、内存、GPU、存储和网络实况并完成基准前，不声明云端模型部署完成。算力不满足独立训练要求时必须先配置训练资源，不能用本机代训冒充云端独立训练。

## 十、验证与验收

### 隔离与现有系统保护

1. 风险系统只通过应用中心进入，并能返回应用中心。
2. 风险组件停止、训练满载和数据库故障时，现有首页、应用中心和业务工作台仍正常。
3. 风险服务账号无法写入现有业务表；风险数据库迁移不连接现有生产业务库。
4. 现有前后端回归测试和关键真实业务流程通过。
5. 在共享 RDS 上施加风险系统峰值连接和查询负载时，现有业务延迟、错误率和连接可用量仍满足发布前基线；停止风险连接后业务指标恢复且没有遗留锁。

### 真实功能闭环

1. 使用真实业务变化生成带来源的评估和结构化研判。
2. 研判中的每项证据可回查到当时的来源快照。
3. 预警、重试、失败和解除均有真实持久化状态。
4. 后续真实结果能生成时间点正确的训练样本，模型输出不会成为自身标签。
5. 数据不足时训练如实跳过；满足门槛时能完成候选训练、影子评估和自动激活。
6. 注入退化候选时自动拒绝；正式模型退化时自动回滚。
7. 应用重启、系统重启和错过计划时间后，训练可以幂等恢复和补跑。

### 界面与可访问性

1. 七个功能中心只展示真实接口返回的数据和状态。
2. 空数据、陈旧数据、服务不可用和权限不足均有明确界面状态。
3. 关键操作刷新页面后仍可依据执行 ID 查看真实进展。
4. 桌面主流分辨率下无信息遮挡；键盘访问、对比度和减少动画设置可用。
5. 视觉验收确认科技感克制、层级清晰、长时间使用不产生明显视觉疲劳。

### 本地和云端完成定义

本地完成需要同时具备：自动启动、真实数据读取、完整研判/预警/结果/训练闭环、模型治理、故障恢复、真实浏览器验收和现有系统无回归证据。页面能打开或单次训练成功不构成本地完成。

云端完成需要在云端实际资源上重新通过上述验收，并额外验证独立训练、本机离线、备份恢复、灰度切换、域名/证书、统一登录和外部真实访问。任何本地成功证据不能替代云端验收。

## 十一、实施顺序

1. 固化独立服务与数据库边界，补齐只读数据契约和权限验证。
2. 打通真实业务变化到风险评估、AI 研判和预警的闭环。
3. 打通最终结果、训练样本、每日训练、影子评估、自动晋级和回滚。
4. 实现长期记忆、假设治理和证据引用。
5. 完成七个功能中心和克制未来科技视觉重构。
6. 安装本地后台服务，完成重启、补跑、故障和现有系统回归验收。
7. 读取云资源实况，选择生产模型与训练规格，完成隔离部署。
8. 完成云端真实访问、独立训练、备份恢复和发布验收。

每一阶段形成边界清晰的提交和可恢复检查点；不得用后续阶段掩盖前一阶段缺失的真实证据。
