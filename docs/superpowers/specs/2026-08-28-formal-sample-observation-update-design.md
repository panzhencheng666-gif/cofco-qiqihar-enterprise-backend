# 已有正式样本观测更新设计

## 目标与边界

本阶段新增“更新已有样本数据”闭环，并完整保留现有“新增样本点、首次填报、批量导入”路径。系统员工可在产情、市场或物流业务页选择一个当前有效、本人有权写入的正式样本，填写实际观测时间与该领域业务数据，点击一次“保存并同步”后即得到正式记录。记录刷新后仍可重查，旧观测不覆盖，并立即参与样本点总揽、对应领域分析与报表；它不得进入地区供需平衡。

本阶段不引入固定日/周频率，不引入草稿、提交、待审核、批准、退回或二次确认，不允许通过观测更新改变样本身份、地区或坐标，不改造既有新增/导入流程，也不扩展地区年度数据或供需平衡功能。

## 方案选择

采用独立的 `FormalSampleObservation` 深模块：对 Web 暴露一个稳定资源接口，模块内部完成样本资格、权限、字段、幂等、正式发布、审计和联动版本计算。它可复用既有领域表、校验规则和正式投影，但不会要求前端串联 create/submit/approve。

不采用以下方案：

- 前端串联既有草稿、提交、批准接口：无法保证单次事务，暴露审核状态，并破坏职责分离语义。
- 为产情、市场、物流各自复制一套公开工作流：会重复权限、幂等、历史与审计规则，且难以维持统一前端契约。

## 领域模型与不变量

`FormalSampleIdentity` 指 `registry.sample_point` 中已经发布、在观测日有效且具备对应领域正式业务关联的稳定身份。其样本点 ID、地区、坐标和既有业务主体是只读绑定。

`OfficialObservation` 是某正式样本在一个领域、产品和实际观测时间下新增的不可覆盖事实版本。每次保存创建新的领域记录；当前有效值由同一样本、领域、产品的正式记录按业务观测时间优先、保存时间和稳定记录 ID 兜底选择最新值。更早的观测仍由历史接口返回。

必须满足：

1. 只有具有领域写权限且地区授权覆盖该样本的系统员工可保存。
2. 样本在 `observedAt` 当日必须处于正式有效期，且已关联请求领域和产品。
3. 请求中的身份字段只接受 `samplePointId`；地区、坐标和主体上下文从正式样本绑定中取得。
4. `Idempotency-Key` 在“员工 + 领域”作用域内唯一；同键同载荷重放返回同一结果，同键不同载荷返回冲突。
5. 正式领域记录、正式样本关联、幂等结果和审计事件在同一数据库事务内完成。
6. 保存结果不出现审核状态或审核动作；技术上可写入既有 `APPROVED/CONFIRMED` 正式态，但只能由本深模块原子完成。
7. 地区供需平衡继续只读取 `regional_production` / 地区年度数据，不查询本模块或样本观测表。

## 后端公开契约

统一前缀 `/api/v1/formal-sample-observations`：

- `GET /eligible-samples?domain&productCode&regionCode&year&observedAt`：返回本人可写的正式样本。每项包含稳定 `samplePointId`、样本名称、领域、产品、地区名称与编码、坐标、有效期、锁定身份摘要及最近一次正式观测摘要；不返回内部工作流状态。
- `POST /observations`，请求头必须带 `Idempotency-Key`。请求体包含 `domain`、`samplePointId`、`productCode`、`observedAt` 和 `payload`。响应包含 `observationId`、`samplePointId`、`domain`、`productCode`、`observedAt`、`officialSavedAt`、`projectionVersion`、`synchronizedModules` 和领域展示值。
- `GET /history?domain&samplePointId&productCode&from&to`：按观测时间倒序返回正式历史，只返回当前员工有读取权限的样本。

领域限定为 `PRODUCTION`、`MARKET`、`LOGISTICS`。后端使用白名单把 payload 映射到既有领域草稿/记录，不允许客户端提交状态、版本、审批人、地区、坐标或样本主体。

错误契约：401 表示未认证，403 表示无写入/读取范围，404 表示样本不存在或不可见，409 表示幂等键载荷冲突或样本不再有效，422 表示观测时间/领域字段不合法。所有错误返回既有统一错误结构和可供 UI 直接说明下一步的业务消息。

## 数据与事务

新增迁移保存独立幂等收据，至少包含：作用域、幂等键、规范化请求摘要、领域记录 ID、样本点 ID、投影版本、首次保存时间及响应快照；数据库唯一约束封闭并发重放。它只保存本功能的命令收据，不复制领域事实。

保存事务先锁定并重查正式样本资格，再按领域调用一个内部 official-observation port。该 port 使用既有领域校验和表结构创建新的正式记录并绑定同一 `sample_point_id`，追加业务审计事件，生成当前投影版本，最后写入幂等收据。任一步失败，全部回滚。

领域正式记录继续是分析、样本点总揽和报表的唯一事实来源。实时刷新通过保存响应的 `projectionVersion` 和现有数据查询失效/重查实现；不另建会与正式投影漂移的前端缓存或影子数据表。

## Web 交互与布局

产情、市场、物流工作区保留原有“新建调查记录/首次填报/批量导入”入口，并在同一菜单下提供两个互斥的页面级工作模式：“采集台账”和“已有样本数据更新”。切换到更新模式时，台账主体整体让位给更新工作区；禁止把更新表单作为临时卡片堆在台账上方。两种模式不复用旧 `newRecord()` 的审核文案或 submit/approve 调用。

宽屏更新工作区按“筛选栏—样本结果列表—正式观测编辑区”组织。筛选栏包含对象类型、业务地区和企业/样本名称关键字；对象类型是可选择的筛选条件。选中样本后，样本的正式对象类型、地区、坐标和主体名称作为锁定身份显示，不允许借观测更新改变身份。编辑区按服务端定义分组展示全部适用字段，底部只保留一个“保存并正式入库”主操作。窄屏按筛选、结果、编辑的顺序单列展开，按钮和输入保持至少 48px 触控高度，禁止固定宽度、横向溢出、遮挡或悬浮覆盖主导航。

视觉采用适合政企数据系统的 IBM Carbon 式原则并保留平台自身品牌：白色与浅灰平面、1px 分隔线、方正 0–4px 圆角、现有企业蓝作为唯一主强调色、4px 间距网格、无装饰性渐变和阴影。信息层级依靠标题、分区、表头和表面色差，不靠彩色大卡片。不得复制 IBM 标识、品牌文案或专有资产。

状态只允许：加载中、未填写、保存中、已保存、保存失败。成功区展示正式保存时间、投影版本和实际同步模块，并自动重查资格列表、历史、当前业务列表和当前页面分析数据。失败保留用户已填内容并提供重试；同一次重试沿用幂等键，修改业务字段后生成新键。

## 2026-08-29 市场对象与字段契约补充

### 查询与锁定身份

`GET /eligible-samples` 增加可选参数 `objectTypeCode` 与 `keyword`。`objectTypeCode` 必须是当前领域、产品下有效的主数据代码；`keyword` 去除首尾空白后最长 100 个字符，只搜索授权范围内的正式样本名称和地区名称。所有条件使用参数化 SQL，并始终先受当前员工地区权限约束，不能通过关键词或类型探测越权样本。

每个 `EligibleFormalSample` 增加 `objectTypeCode` 与 `objectTypeName`。Web 的对象类型下拉使用既有主数据接口，查询参数和响应字段使用同一代码集。对象类型在筛选栏可选；选中正式样本后为只读身份。保存请求仍只提交 `samplePointId`，服务端在事务内重查并锁定样本，从最新正式关联取得对象类型、地区、坐标和主体，忽略或拒绝客户端伪造的身份字段。

### 元数据驱动的完整表单

Web 不再维护 `fieldsByDomain` 业务字段硬编码。选中样本后按 `domain + productCode + objectTypeCode` 加载现有正式定义接口，并遵循定义中的显示状态、顺序、控件类型、单位、精度、必填性、选项和分组：

- 市场领域完整渲染 `MarketDefinition.coreFields` 与 `groups[].fields`，排除由服务端锁定覆盖的样本名称、对象类型、地区、坐标、填报人及由实际观测时间派生的业务日期字段。
- 产情和物流领域使用各自现有正式定义/公共字段契约，采用同一适用性规则；不得用少数字段列表替代完整定义。
- 最近正式观测值只给定义中当前适用的字段预填。定义未返回的字段不显示、不提交；客户端即使伪造，服务端也按同一定义拒绝。
- 表单 payload 组装使用定义中的字段归属，而不是依靠代码前缀猜测 `coreValues` 与 `facts`。

市场价格适用性按本次确认调整：

- `DEEP_PROCESSOR`（深加工企业）、`FEED_MILL`（饲料厂）、`BREEDING_FACTORY`（养殖场）不适用 `MKT_SALE_BASE_PRICE`，只采集 `MKT_PURCHASE_BASE_PRICE` 及该产品/对象类型定义的其他采购、加工、质量、库存字段。
- 其他市场对象类型保持现有正式元数据规则；是否显示销售基础价完全由服务端定义返回决定，前端不自行推断。
- 新迁移只修改字段适用性/必填元数据，不重写历史记录。既有历史销售价仍可在历史记录中追溯，但不能被带入上述三类对象的新观测请求。

市场领域服务端保存解析必须与定义同步：对当前定义未包含的字段拒绝保存；对定义中必填字段缺失返回 422；对可选字段允许空值。不得继续无条件读取 `SALE_BASE_PRICE`。保存成功响应中的 `values` 来自落库后重查，不得原样回显未经验证的客户端 payload。

### 契约闭环门槛

本阶段不得以“前端隐藏销售价”作为完成。必须同时具备以下自动化证据：

1. 后端定义测试证明上述三类对象不返回销售基础价，贸易商等未调整类型仍按正式定义返回；保存测试证明缺少不适用销售价可成功，伪造销售价被拒绝，缺少适用必填字段被拒绝。
2. 资格列表测试证明对象类型与关键词组合筛选、空结果、非法类型、关键词长度、地区越权和观测日失效均按统一错误契约处理。
3. Web repository 契约测试固定查询参数名称、对象类型响应解析、定义加载、`Idempotency-Key`、POST 载荷和错误传播。
4. Web 页面测试证明两个工作模式互斥、对象类型筛选可选、名称搜索可用、选中身份不可修改、三类对象无销售基础价、全部适用字段按定义显示、保存失败保留输入并沿用幂等键、修改后换键。
5. 真实本地验收通过网络请求核对 GET 定义、GET 资格、POST 保存与保存后 GET 重查的代码和值一致；保存后刷新总揽、市场分析和报表，地区供需平衡版本与结果保持不变。

### 安全与失败语义

对象类型、关键词、产品、领域、观测时间和业务字段全部由服务端白名单校验。查询使用参数化 SQL；保存前重新执行权限、有效期和对象类型适用性检查，避免陈旧筛选结果越权写入。幂等键仍由“员工 + 领域”唯一约束和事务锁封闭并发重复；同键同规范化载荷返回同一正式结果，同键不同载荷返回 409。错误信息只返回业务代码和可操作提示，不泄露 SQL、内部 ID 映射、授权范围或堆栈。

## 测试接缝

本阶段确认以下公共接缝，测试只通过这些边界观察行为：

1. 后端 REST 接缝：资格列表、一次保存、幂等重放/冲突、历史重查、权限和有效期。
2. 正式读取接缝：保存前后通过既有总揽、对应分析和报表 API 重查，证明新记录成为当前值、旧记录仍在；地区供需 API 的地区数据版本和结果不变。
3. Web repository 接缝：请求路径、`Idempotency-Key`、响应解析与错误传播。
4. Web 页面接缝：两个入口并存、锁定身份、单按钮保存、真实状态、成功后重查、失败可重试和窄屏无溢出。

测试按垂直切片红绿推进，不模拟内部模块调用；数据库集成测试只使用受保护的 `qiqihar_enterprise_test`。

## 验收与发布

完成聚焦测试后，仅对受影响仓运行既有标准回归、格式/lint/架构/构建。使用现有本地发布脚本安全同步源码构建产物到 8090、63200、63182，并核对产物 SHA-256 与健康状态。

真实 63182 验收使用本地系统员工身份完成一次现有样本保存，刷新页面后重查仍在，核对总揽、相应分析和报表同步，核对地区供需不受影响，并检查桌面与窄屏的空态、加载态、错误态及无遮挡。HTTP 200、构建成功和浏览器业务验收分别记录，不互相替代。

## 2026-08-29 台账与更新字段统一补充

“采集台账”和“已有样本数据更新”必须展示同一服务端正式字段定义，不能继续由台账的前端静态矩阵、硬编码表头或被丢弃的定义响应形成第二套业务口径。产情、市场、物流均遵守以下规则：

- 样本名称、对象类型、地区、经纬度、填报人、业务时间和状态属于台账身份/追溯列，不在更新表单中重复编辑。
- 其余可填业务字段以对应产品、对象类型的正式定义为唯一来源；字段名称、分组、顺序、单位和适用性在台账与更新页一致。
- 台账当前页存在多种对象类型时，合并当前页各对象类型的正式定义并按服务端分组顺序去重展示；某条记录不适用或没有值的字段显示“—”，不得伪造为零。
- 深加工企业、饲料厂、养殖场不显示销售基础价，台账和更新页同时遵循服务端排除规则。
- 正式定义读取失败时，台账显示可操作错误，不退回旧静态字段矩阵；新增、首次填报和批量导入入口保持原语义。
- 统一只影响展示和普通观测载荷的字段契约，不允许借此修改样本身份、坐标或地区供需数据。

筛选区采用同一高度和基线：桌面端标签占一行，输入、下拉和查询按钮使用显式一致高度；窄屏使用至少 48px 触控高度。工作台保持平面分区、1px 分隔线和现有企业蓝，不增加弹窗、向导、阴影或装饰性卡片。
