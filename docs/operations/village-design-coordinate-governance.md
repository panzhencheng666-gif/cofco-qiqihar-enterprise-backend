# 2,332 个行政村设计坐标治理

## 目的和边界

本流程对无年份的行政村设计点做**只读证据盘点**。设计点的分母是
`platform.region` 中全部 `VILLAGE` 行政村：齐齐哈尔市 1,197 个、呼伦贝尔市
571 个、黑河市 564 个，共 2,332 个；不得缩减为齐齐哈尔市单一范围。

它不导入、移动、修正或审核坐标，也不创建 `registry.sample_point`。2,332 个
坐标行齐全只说明审计输入完整，绝不表示 2,332 个点已审核。审计脚本只允许连接
本机 `127.0.0.1:5432/qiqihar_enterprise_dev`，并在每次连接中以只读事务运行。

## 来源、法律依据与可追溯性

当前受控批次来自“中华人民共和国民政部国家地名信息库”，来源页面为
`https://dmfw.mca.gov.cn/9095/stname/listPub`，修订版 `2025-12-31`。本次盘点的
取得/核对日期为 2026-08-23，受控批次元数据为：

| 项目 | 值 |
| --- | --- |
| 数据集 SHA-256 | `f3cfdaa80b9836514caaa5d496137cce27bf1971fb8b8d5596542d04cbb53799` |
| 源工作簿 SHA-256 | `dea2df64a09e9fe8718f415cd58c860a462d0e0b6692ade46b8a4f64b0ee4264` |
| 坐标原始坐标系 / 展示坐标系 | EPSG:4490 / EPSG:4326 |
| 审计算法版本 | `v1.0.0-20260823` |

《地名管理条例》确立民政部维护国家地名信息库、公布标准地名并便利公众使用的法定
职能。这是本地逐点核验和内部公共使用说明的依据；但本地尚未记录捕获工作簿的明确

也不得据此扩大分发范围。取得书面许可前，审计 CSV 只保留在被忽略的本地证据目录。

## 审计算法和不可绕过的限制

算法 `v1.0.0-20260823` 以行政村内部代码为唯一分母，并要求每个村同时具备：

1. `TOWNSHIP → COUNTY → PREFECTURE` 完整父级链；
2. 一条对应的 `platform.region_location`；
3. 对应的受控 `platform.geography_import_batch` 来源和哈希。

脚本在导出前还将受控输入身份闭合为：呼伦贝尔 `150700=571`、齐齐哈尔
`230200=1197`、黑河 `231100=564`；全部 2,332 行必须同时使用上述来源/修订、数据集
SHA-256 和源工作簿 SHA-256。脚本断言村数、位置行数、唯一村代码数都恰为 2,332，且
CSV 只有一行表头和 2,332 行数据。每行原始和 WGS84 坐标都以 EWKT 直接输出，禁止
格式化、最近距离回填或移动。
它同时记录官方地点 ID/代码/标准名称/区域字段、匹配方式和置信度、存储审核状态、
重复坐标成员、名称/层级异常以及来源元数据。

不存在可作为本流程依据的权威地市、区县、乡镇边界多边形表。系统生成的展示面仅供
地图渲染，不能用于判断点是否落区、批准、拒绝或移动坐标。因此每一行的
`spatial_authority_status` 固定为
`PENDING_AUTHORITY_NO_AUTHORITATIVE_PREFECTURE_COUNTY_TOWNSHIP_POLYGONS`，最终状态必定是
`PENDING_*`，不得在本流程中写出或推导 `REVIEWED`。

## 状态和异常处置

`stored_review_status` 是数据库中既存的历史匹配/治理输入；`final_governance_status` 是
本次审计的独立保守结论，不会覆盖或把前者升级为后者。即使历史字段为 `REVIEWED`，
最终字段仍必须是 `PENDING_AUTHORITY_REVIEW_STATUS_REQUIRES_RECHECK`。守卫只检查最终
状态列，绝不因历史字段包含 `REVIEWED` 而拒绝导出。

| 结论 | 含义和处置 |
| --- | --- |
| `PENDING_SPATIAL_AUTHORITY_<stored status>` | 坐标未获权威行政边界空间核验；保留原值，等待权威边界和独立复核。 |
| `PENDING_AUTHORITY_REVIEW_STATUS_REQUIRES_RECHECK` | 即使存储状态为 `REVIEWED`，本脚本仍不得认可，必须以本流程的权威边界重新核验。 |
| `*_NAME_*` / `*_HIERARCHY_*` | 名称或层级匹配异常；进入按区划码、乡镇和标准名称的人工核验清单。 |
| `NON_ADMINISTRATIVE_PLACE_TYPE` | 官方地点类型不是行政村；不得把点当作村委会驻地或用最近点替换。 |
| duplicate coordinate group | 只是同坐标证据组，不等同于同一实体；应单独调查合法共址、数据重复和证据不足。 |

名称/层级异常独立于既存审核状态计算，并可在同一行叠加：缺失或非 20 位官方地点代码、
缺失或非 9 位官方区域代码、官方区域代码与父乡镇代码不一致、官方地点代码前 9 位与
官方区域代码不一致、缺失/变体官方标准名称，以及非行政村地点类型。这些字段只产生
审计异常，不授权自动更改坐标。

例外处理必须由资料提交人与审核人分离：资料人员提供可再核验的官方出处、区划码、
村委会驻地或经审核代表位置依据；独立审核人核对层级、名称、坐标系和许可后，才可在
另行批准的受控导入/修正任务中更新原稳定记录。更新后重新运行本审计和下游地图复查。
不得以展示面、距离、名称相似或本审计 CSV 直接批量升级状态。

## 运行、输出和复核边界

从 Backend 仓库根目录运行：

```sh
./scripts/audit-village-design-coordinates.sh \
  --database qiqihar_enterprise_dev \
  --output .local-runtime/evidence/village-design-coordinate-audit-20260823.csv
```

脚本会在输出前验证精确数据库名、数值 loopback 服务器/端口、`transaction_read_only=on`
以及三项 2,332 断言和固定的三地/来源/双哈希身份；任何失败均不会留下成功证据。
输出只能是物理仓库目录 `.local-runtime/evidence/` 内、未被 Git 跟踪且文件名安全的
`.csv` 文件；仓库外路径、跟踪路径和符号链接目录一律拒绝。临时 CSV 必须在全部汇总
查询成功后才原子替换最终证据，失败不会留下新的表面成功文件。标准输出只提供来源/
修订、审核状态、重复坐标、缺失行和名称/层级异常的计数，不显示密码或连接凭据。

输出路径位于 `.local-runtime/`，受 `.gitignore` 保护，只能作为本地审阅证据。哨兵
校验只证明其哈希的村代码、原始坐标和存储审核状态未变，不证明所有治理列或外部来源
始终不变。提交中
可包含脚本、守卫测试和本治理说明，绝不能包含 CSV、原始工作簿、数据库、日志或截图。
